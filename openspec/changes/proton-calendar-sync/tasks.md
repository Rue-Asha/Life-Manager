# Tasks: proton-calendar-sync

Waves: 1 → U1 · 2 → U2 ∥ U3 ∥ U4 · 3 → U5 ∥ U6 · 4 → U7.

Every task that adds behaviour starts with its scenario tests, named `Scenario: <title>` and written from the THEN
clauses, run red for the stated reason before the code. `npm run proof` after every task; `npm run proof:full` (in the
background; a red run is rerun in full) at the end of every unit that touched an e2e file or a page an e2e test walks.
Unit tests use `openDb(':memory:')` and `createFake(<mkdtemp dir>)`; counts are derived from the seeded DB or from
domain-function results, never assumed. e2e: seed through `__test/seed`, call `setClock` again after every `reset()`,
run `npm run build` before a single-file e2e run and after each edit, wait for the URL or heading after client-side
navigation, assert call-log deltas (length before/after), and scope count assertions to a container test id.
Contracts, argv, test ids: design.md ## Contracts.
